## 4. 경로 알고리즘 관련 코드 현황

키워드(`route/waypoint/hotspot/geohash/buffer/score/penalty/swap/avoid/Tmap/Directions`) 매칭 파일:
`route_repository.dart`, `route_notifier.dart`, `route_models.dart`, `plogging_session_providers.dart`, `plogging_session_screen.dart`.

### Waypoint 알고리즘(`Score_i = α·S_i − β·D_i − γ·avoid_penalty_i`) 이식 여부

❌ **Flutter에 미이식 — 설계상 서버(FastAPI) 책임.** 단, 알고리즘 **산출물 DTO는 완비**되어 있음:
- `route_models.dart`의 `RouteHotspot`이 `S_i`(감시밀도 점수), `avoid_penalty`를 필드로 보유.
- `RouteResult`가 `polyline`, `k3_hotspots`(K=3 경유지, 방문순서=배열순서), `n_swaps`(2-opt swap 횟수), `is_hard_case`, `intersection_m/ratio`, `crossed_uqa_codes`(회피영역) 등 알고리즘 출력 전체를 매핑.
- 즉 점수계산·핫스팟선정·swap 최적화 로직 자체는 Flutter에 없고, 결과만 수신·표현.

> ⚠️ **가이드라인 불일치 발견:** CLAUDE.md §6은 "Waypoint 알고리즘(K=3)을 route_notifier(Flutter)에서 수행"으로 명시했으나, 실제 구현은 **전량 서버측**으로 이전됨. 또한 §6은 도보경로를 **Naver Directions 5**로 규정하나, `route_repository.dart` 주석은 **Tmap Pedestrian API**(서버가 최대 6회 호출)를 전제로 함. → 보고서/문서 정합성 갱신 필요.

### API 연동 현황
- **Tmap / Naver Directions 직접 호출:** Flutter에는 없음(원칙대로 서버 경유). Flutter는 `POST /route/recommend` 단일 엔드포인트만 Dio로 호출.
- `route_repository`는 실 구현: BaseOptions(receiveTimeout 120s — hard case 대비), 502→도보경로 실패 사용자 메시지, RouteException 처리까지 완성.

## 핵심 시사점 (발표 보강용)
